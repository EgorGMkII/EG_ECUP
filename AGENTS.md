# Правила и инструкции для агентов (AGENTS.md)

## 1. Описание проекта и его цель
- **Проект**: Соревнование OZON ECUP по предсказанию User LTV (суммарного GMV).
- **Цель**: Предсказание суммарных трат каждого из 250 000 пользователей за следующие 30 дней по историческим логам поисков и покупок.
- **Задача**: Построение воспроизводимого, быстрого и высокоточного ML-пайплайна (предобработка данных в Polars, валидация по якорным датам, обучение моделей CatBoost/LightGBM/NN и генерация сабмитов).

## 3. Стандарты стиля кода и нативные оптимизации

### 🚨 ГЛАВНОЕ ПРАВИЛО: Нативные методы вместо «велосипедов»
**Категорически запрещено** писать кастомные медленные циклы в Python или изобретать алгоритмы с нуля там, где есть готовые высокопроизводительные решения!

1. **Работа с данными (Polars)**:
   - Использовать нативный **Expression API** (`pl.Expr`) и векторные операции (`pl.when().then().otherwise()`).
   - Применять параллельную группировку `.group_by().agg()` вместо итерации по строкам/группам.
   - Использовать **Lazy API** (`pl.scan_parquet()`) и **Streaming Engine** (`.collect(streaming=True)`) для тяжелых вычислений.
   - Строго контролировать память: использовать батчинг по пользователям для защиты от OOM.

2. **Машинное обучение (CatBoost / LightGBM / XGBoost)**:
   - Использовать встроенные специализированные функции потерь для данных с преобладанием нулей и длинным хвостом (`Tweedie`, `RMSELog` / `RMSLE`, `Huber`).
   - Использовать нативную поддержку GPU (`task_type="GPU"`) и встроенную обработку категориальных признаков.
   - Не делать ручных итераторов, если в библиотеке есть встроенный `Pool` / `Dataset` с поддержкой подгрузки данных.

3. **Структура и качество кода**:
   - Весь переиспользуемый код выносить из ячеек ноутбуков в модули папки `src/`.
   - В ячейках ноутбуков оставлять только краткие вызовы функций, анализ и визуализацию.
   - Прописывать явные **Type Hints** (`typing`) и краткие информативные docstrings.
