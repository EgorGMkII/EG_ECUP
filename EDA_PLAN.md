# План EDA (Exploratory Data Analysis)

## Этап 1. Аудит данных и корректности витрины

Это необходимо сделать первым: иначе можно красиво исследовать неверно интерпретированные признаки.

### 1.1. Проверить гранулярность
Убедиться, что одна строка действительно соответствует одной паре: `user_id × event_date`.
Проверки:
- число дубликатов `(user_id, event_date)`;
- число пропусков в ключевых колонках;
- диапазоны бинарных флагов — действительно ли только `{0, 1}`;
- отсутствие отрицательных значений в счётчиках и GMV;
- отсутствие NaN и бесконечностей;
- число уникальных пользователей по датам.

### 1.2. Проверить логические связи полей
Например:
- `has_search_to_cart == (search_to_cart > 0)`
- `has_search_to_ord == (search_to_ord > 0)`
- `has_cat_to_cart == (cat_to_cart > 0)`
- `has_cat_to_ord == (cat_to_ord > 0)`

Также проверить:
- `search_to_cart <= to_cart`
- `search_to_ord <= to_ord`
- `cat_to_cart <= to_cart`
- `cat_to_ord <= to_ord`
- `gmv_search <= gmv`
- `gmv_cat <= gmv`

И отдельно:
- `to_ord == search_to_ord + cat_to_ord`?
- `gmv == gmv_search + gmv_cat`?

Последние равенства нельзя предполагать заранее: общие итоги могут содержать другие каналы. EDA должен показать долю совпадений и распределение разницы.

### 1.3. Уточнить семантику пропущенных дней
Датасет разреженный. Нужно установить:
- отсутствие строки означает полное отсутствие активности;
- либо какие-то дни/события могли не попасть в таблицу.

Это особенно важно для `mean` и `std`: сейчас они считаются по существующим строкам пользователя, то есть фактически по активным дням, а не по всем календарным дням окна.

### 1.4. Стандарт наименования и структура окон
*Уже зафиксировано и реализовано в `src/data.py`:*
- **Кумулятивные окна (общий объем истории)**:
  - `30d`: `[t-29 ... t]` (последние 30 дней)
  - `60d`: `[t-59 ... t]` (последние 60 дней)
  - `90d`: `[t-89 ... t]` (последние 90 дней)
- **Лаговые неперекрывающиеся бакеты (динамика)**:
  - `30_60d`: `[t-59 ... t-30]` (второй месяц назад)
  - `60_90d`: `[t-89 ... t-60]` (третий месяц назад)

## Этап 2. Общая временная структура данных

### 2.1. Полнота данных по времени
По каждой дате посчитать:
- число строк;
- DAU;
- число пользователей с поиском;
- каталогом;
- корзиной;
- заказом;
- положительным GMV;
- общий `searches`, `to_cart`, `to_ord`, `gmv`.

Это позволит увидеть:
- пропуски и технические провалы;
- выбросы;
- праздники и распродажи;
- изменение состава данных.

### 2.2. Сезонность
Посмотреть агрегаты по:
- дню недели;
- неделе;
- месяцу;
- рабочим и выходным дням.

Причём нужны не только абсолютные суммы, но и значения на активного пользователя: `GMV / DAU`, `orders / DAU`, `searches / DAU`.
Иначе рост GMV может объясняться просто ростом числа активных пользователей.

### 2.3. Изменение пользовательской базы
Для каждой даты или недели:
- новые пользователи;
- вернувшиеся;
- продолжающие активность;
- давно неактивные;
- возраст пользователя с момента первой активности.

Это важно, потому что финальный `test` может содержать пользователей с другой длиной истории, чем ранние фолды.

## Этап 3. Полный анализ таргета по всем фолдам

### 3.1. Сравнить распределения между фолдами
Для каждого фолда вывести таблицу:

| Показатель | fold_00 | fold_01 | fold_02 | fold_03 |
| :--- | :---: | :---: | :---: | :---: |
| Доля `target = 0` | | | | |
| Среднее | | | | |
| Медиана | | | | |
| 90-й квантиль | | | | |
| 99-й квантиль | | | | |
| Суммарный GMV | | | | |

Это покажет temporal drift и сезонность.

### 3.2. Исследовать `log1p(target)`
Построить рядом:
- исходное распределение `target`;
- распределение только положительного `target`;
- распределение `log1p(target)`.

Поскольку метрика — RMSLE, именно логарифмическое пространство является основным для моделирования и анализа ошибок.

### 3.3. Измерить концентрацию GMV
Посчитать долю общего GMV, создаваемую:
- `top 0.1%`;
- `top 1%`;
- `top 5%`;
- `top 10%`.

Это покажет, насколько результат определяется небольшой группой суперпокупателей.

---

## Этап 4. Переходы между прошлым и будущим

Это один из наиболее полезных блоков конкретно для нашей задачи.

### 4.1. Матрица покупательских состояний
Для каждого фолда рассчитать категории:

| Прошлый GMV | Будущий GMV | Интерпретация |
| :---: | :---: | :--- |
| `0` | `0` | стабильно не покупает |
| `0` | `>0` | новый или вернувшийся покупатель |
| `>0` | `0` | временно перестал покупать |
| `>0` | `>0` | сохранившийся покупатель |

Нужно посчитать размер каждой группы и её долю.
Это прямо покажет:
- насколько хороша авторегрессия;
- насколько сложна классификация `target > 0`;
- сколько пользователей невозможно предсказать только по прошлому GMV.

### 4.2. Стабильность положительного таргета
Для каждого пользователя определить, в скольких из четырёх фолдов `target > 0`.
Получим группы:
- `0/4` — устойчиво непокупающие
- `1/4` — эпизодические
- `2/4`
- `3/4`
- `4/4` — регулярные покупатели

### 4.3. Авторегрессионные бейзлайны
До CatBoost проверить:
- `pred = GMV` предыдущего 30-дневного периода;
- среднее последних двух периодов;
- среднее последних трёх периодов;
- взвешенное среднее с повышенным весом свежего периода;
- shrinkage к глобальному среднему.

Сравнивать сразу по RMSLE. Это даст настоящую нижнюю границу, которую обязан обойти CatBoost.

## Этап 5. Анализ пользовательской активности и RFM

### 5.1. Recency
Нужно добавить и исследовать:
- `days_since_last_activity`
- `days_since_last_search`
- `days_since_last_cart`
- `days_since_last_order`
- `days_since_last_positive_gmv`

Затем построить $P(\text{target} > 0 \mid \text{recency bucket})$ по бакетам: `0–7`, `8–14`, `15–30`, `31–60`, `61–90`, `90+`, `«никогда»`.

### 5.2. Frequency
Посчитать:
- число активных дней;
- число дней с поиском;
- число дней с корзиной;
- число дней с заказами;
- суммарное число заказов;
- средний и медианный интервал между покупками.

### 5.3. Monetary
Кроме суммы GMV:
- средний GMV на заказ;
- средний GMV на покупочный день;
- максимум;
- медиана;
- вариативность;
- число положительных GMV-дней.

После этого проверить зависимость будущего GMV от RFM-групп.

## Этап 6. Анализ воронки

У нас сейчас почти полностью проигнорированы `to_cart`, `to_ord`, канал поиска и канал каталога.

### 6.1. Сила этапов воронки
Сравнить:
- $P(\text{target} > 0 \mid \text{нет активности})$
- $P(\text{target} > 0 \mid \text{только поиск})$
- $P(\text{target} > 0 \mid \text{корзина})$
- $P(\text{target} > 0 \mid \text{прошлый заказ})$

### 6.2. Конверсионные признаки
Исследовать:
- `to_cart / searches`
- `to_ord / to_cart`
- `to_ord / searches`
- `gmv / to_ord`

Отдельно:
- `search_to_cart / searches`
- `search_to_ord / searches`
- `cat_to_ord / cat_active_days`

Нужны сглаживание и отдельный флаг нулевого знаменателя.

### 6.3. Поиск против каталога
Сегменты:
- только Search;
- только Catalog;
- оба канала;
- ни одного;
- покупка через Search;
- покупка через Catalog;
- смешанный сценарий.

Проверить для них:
- вероятность будущей покупки;
- медианный будущий GMV;
- zero rate;
- стабильность между фолдами.

## Этап 7. Динамика пользователя

Сумм недостаточно: важно понять, растёт активность или затухает.

Добавить и исследовать:
- `gmv_30d - gmv_30_60d`
- `gmv_30d / (gmv_30_60d + eps)`
- `searches_30d - searches_30_60d`
- `orders_30d - orders_30_60d`

Также:
- линейный тренд по недельным агрегатам;
- число недель с покупкой;
- текущая серия неактивности;
- ускорение/замедление поисковой активности.

Затем проверить зависимость `target > 0` и `log1p(target)` от направления тренда.

## Этап 8. Анализ признаков перед моделированием

### 8.1. Не ограничиваться Pearson correlation
Текущая корреляция показывает только линейную связь и плохо работает с zero-inflated heavy-tail таргетом.

Нужно дополнительно:
- Spearman correlation;
- корреляции с `log1p(target)`;
- связь с бинарным `target > 0`;
- mutual information — позже, на выборке;
- однофакторный CatBoost/AUC для отдельных признаков — тоже позже.

### 8.2. Мультиколлинеарность и дублирование
`sum`, `mean`, `max` и разные окна могут быть почти копиями друг друга. Для CatBoost это не критическая проблема, но анализ поможет понять, какие признаки реально несут новую информацию.

### 8.3. Train–validation drift
Сравнить распределения признаков между временными фолдами:
- zero rate;
- среднее и квантили;
- PSI или KS statistic;
- долю пользователей вне диапазона предыдущих фолдов.

Особенно важен drift между `fold_02` и `fold_03`.

## Этап 9. EDA, ориентированный на качество модели

После первого CatBoost анализировать уже не просто данные, а ошибки.

Срезы RMSLE:
- реальные нули;
- положительные таргеты;
- новые покупатели;
- ушедшие покупатели;
- регулярные покупатели;
- пользователи без прошлых заказов;
- `top 1%` по target;
- Search/Catalog-сегменты;
- recency-бакеты.

Также проверить:
- средний прогноз на реальных нулях;
- долю общего GMV, которую предсказала модель;
- калибровку вероятности `target > 0`;
- где модель систематически завышает или занижает прогноз.
